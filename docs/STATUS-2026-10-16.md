# Project status: hpqv v2 (2026-10-16)

Branch: `feat/secure-session-v2`, local only and **not pushed**. v1 lives on
`experiment/cain` and in release v0.1.0-demo.1. All historical results in
`results/` are untouched.

## 1. What we are building

A **course-project proof of concept**: a real-time voice-call app that is:

- **Post-quantum secure.** Calls are set up over TCP with TLS 1.3, using a
  *hybrid* key exchange: classical X25519 plus quantum-safe ML-KEM-768
  (X25519MLKEM768). Each device proves who it is with an ML-DSA-65 signature
  key.
- **Low-latency.** Voice goes over UDP as small encrypted Opus packets (at most
  1200 bytes, so they never fragment). Packets have their own replay protection
  and integrity checks.
- **Easy to use on the same Wi-Fi.** Devices find each other on the network. The
  two people read a 6-digit code to each other once, and from then on the app
  trusts that friend automatically. No files to swap, no IP to type.
- **Demonstrable and measurable.** It has a live GUI, network-impairment demos
  and fresh benchmark results. It is honest about what is verified and what is
  not.

The goal is a working, well-documented prototype with credible security, not a
production product.

## 2. What we replaced from v1, and why

| Area | v1 (before) | v2 (now) |
|---|---|---|
| Identity | One shared file holding **both** people's secret keys, so either could impersonate the other | Each device has its own private key; only public certificates or pairing are used |
| Handshake | A hand-written protocol (replayable, partly unchecked) | Real **TLS 1.3**: X25519MLKEM768 key exchange, mutual ML-DSA-65 authentication |
| Control messages | Plain text, so hang-up and key rotation could be faked | Inside TLS: encrypted and impossible to fake, replay or reorder |
| Voice keys | One key for both directions | A separate key per direction, derived from the TLS session |
| Voice packets | No replay protection; bad packets silently ignored | Call ID, replay window, strict size checks, per-reason reject counters |
| Memory safety | 4 bytes could trigger a huge allocation (200 MB measured) | Hard size limits everywhere |
| Crypto library | liboqs (version-mismatched) | `cryptography` 50.0.1 (bundled OpenSSL 4.0.2) + pyOpenSSL 26.4.0, checked against NIST test vectors |
| Setup | Copy an identity file, type an IP | Pair once with a 6-digit code (or still use files if you want) |

## 3. What has succeeded (built, tested, committed)

### Research and decisions
- **X-Wing was checked and then not used.** It is a hybrid KEM, validated
  against 3 + 10 official test vectors. Using it would have meant writing our own
  handshake, so we chose real TLS 1.3 instead.
- **The real TLS route was proven before committing to it.** It runs from Python
  through pyOpenSSL, and interoperates with Go's TLS stack.
- **The standards were checked:**

  | Standard | Covers | Status |
  |---|---|---|
  | RFC 9846 | TLS 1.3 | RFC |
  | RFC 10024 | X25519MLKEM768 | RFC |
  | RFC 9881 | ML-DSA in certificates | RFC |
  | RFC 9266 | channel binding | RFC |
  | draft-ietf-tls-mldsa | ML-DSA inside TLS | still a draft |

### Phase B: security foundation (commits `92412b4` … `932fb1f`)
- **TLS 1.3 secure channel** (`secure.py`): hybrid group only, ML-DSA-65 both
  ways, pinned keys, a READY step, no fallback to classical.
- **Encrypted UDP voice** (`packet.py`, `replay.py`, `keyring.py`): per-direction
  keys, replay window, size checks, live key rotation.
- **Per-device identities** (`identity.py`) with protected private-key files.
- **Everything wired into the CLI, the call loop, the GUI and telemetry.**
- **liboqs removed.** The v1 experiments were ported to `cryptography` and kept
  reproducible.
- **Independent security review (T6, an AI reviewer)** found no break of
  authentication or secrecy, and 6 smaller issues.

### Phase B1: review fixes (commit `61eadd1`)
- The first handshake message offers **only** the hybrid group and ML-DSA-65.
  Verified on the wire, and against Go.
- Using the same identity on both machines is refused.
- Private-key file permissions are enforced. On Windows this uses ACLs, tested
  only with simulated Windows behaviour so far.
- Voice keys can be taken only once, and safely across threads.
- On Windows, a junk or oversized packet can no longer end a call.

### Phase B2: no-files pairing (commit `d47edef`, experimental)
- A **separate pairing connection** (ALPN `hpqv-pair/1`), which can never become
  a call.
- A **commit-then-reveal 6-digit code** bound to the TLS session. Both users must
  confirm. A friend is saved only after both said yes.
- **Pairing window:** 2 minutes, one pairing at a time, at most 3 attempts, and it
  closes on a mismatch.
- **Friend store** keyed by fingerprint, saved safely and never silently replaced.
- **Network pieces:** LAN discovery (an untrusted list), and a listener that
  survives stray connections.
- **CLI:** `pair --allow`, `pair <device>`, `peers`, `forget`. `listen` and
  `call` work with paired friends.
- **GUI:** a "Pair a device" box.

## 4. What still needs to be done

In your priority order. Each phase ends with real test results and a stop for
review.

### C1: reliable calls and clean shutdown (next)
- Detect a peer that has gone silent: a ping every second, and the call ends
  after about 10 seconds of silence.
- Move the remaining call listeners (file-mode CLI and GUI listen) onto the new
  listener, which keeps accepting connections.
- Clean hang-up and window close, with every thread finished within a few
  seconds.

### C2: continuous playback and better audio repair
- A steady 20 ms playback clock and a bounded jitter buffer with adaptive depth.
- Rebuild a lost frame from the next packet's FEC data, otherwise conceal it.
- Count underruns.

### D1: Diagnostics tab
- **Security:** protocol, group, fingerprints, code, key generation.
- **Network:** loss, jitter, round-trip time, rejected packets.
- **Audio:** buffer level, FEC/PLC events, underruns.
- Mark every value as measured or estimate. Add reset and CSV/JSON export.

### D2: impairment demos and fresh benchmarks
- Named, repeatable network profiles: loss, burst, delay/jitter, outage.
- Compare FEC off against FEC on.
- Benchmark the hybrid handshake against a classical-only one, kept isolated.
- Fresh results in `results/v2/`, produced by committed scripts.

### E: setup and demo
- A setup guide, a 5-minute demo script and README updates.

### Open items and limitations to keep in mind
- **Windows has never been tested on a real machine,** or even in CI, because
  nothing has been pushed. GitHub's Windows runners are Windows **Server**; real
  Windows 10/11 needs physical PCs. Known Windows work: verify key ACLs for real,
  the exclusive port binding, firewall prompts, and audio devices.
- **The GUI window has not been opened in this session.** Only its logic is
  tested.
- **Two-machine discovery over real Wi-Fi** has not been tried; only loopback.
- **The pairing code is our own construction** of a published pattern. It is not
  formally verified or externally reviewed. It only protects users who actually
  compare the code.
- **Nobody outside this thread has reviewed the security,** and ML-DSA inside TLS
  is still a draft standard.
- **Not pushed to GitHub.** That needs your permission.
